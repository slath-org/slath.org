A self-hosted code forge where Git and Jujutsu users work on equal terms

Slath is a secure, lightweight forge you run yourself. A small installation needs only Slath, PostgreSQL, Git, and OpenSSH. It's free software under the AGPL.

Early development. Slath isn't usable yet. Configuration, storage layout, and interfaces will change without notice. This page describes what works today and what's planned.

For self-hosters

Small enough to run on one machine

Slath is a single Rust binary. It doesn't need Kubernetes, Redis, a hosted account, or anything on the internet once it's installed.

  • Four parts, all of them familiar

    Slath, PostgreSQL, system Git, and the OpenSSH server you already run. Background jobs use a queue in PostgreSQL. Repositories and uploads live on the local filesystem.

  • Security boundaries you can check

    Git runs only through a hardened process runner with a scrubbed environment. SSH helpers never see database credentials. Hooks that can't reach the server reject the push instead of letting it through. CI jobs run on separate runner hosts, never on the forge.

  • Self-contained and air-gap friendly

    Every font, icon, and script is served by your instance. No CDNs, remote fonts, analytics, or avatar services.

  • Upgrades in one command (planned)

    Upgrades from any earlier release are planned as a single command, with preflight checks, an automatic backup, and a tested way back.

For Git and Jujutsu users

Review changes, not just branches

Plain Git clients clone, fetch, and push over HTTPS and SSH with the standard protocols. Jujutsu is first-class too: Slath follows a change across rewrites, so reviews survive rebases and amends.

A change keeps its identity however often you rewrite it. Slath reads that identity from either of two places:

  • the change-id header that jj writes into Git commits, or
  • a Change-Id: trailer in the commit message, for Git users and existing Gerrit-style tooling.

On top of that, merge requests will show each revision of a change, interdiffs between revisions, and stacks of dependent changes that can be reviewed one by one and landed partially, from the web or by pushing.

Merge requests and stacks are planned. Today Slath serves Git over smart HTTP (protocol v0 and v2) and over SSH, and its test suite runs jj git clone and jj git push over both for every supported jj version.

Federation

ForgeFed: after 1.0, on solid ground

Slath 1.0 won't federate. We'd rather say that plainly than promise a half-working protocol.

ForgeFed lets issues, merge requests, and follows cross instance boundaries. Experiments with it are on the roadmap for the 2.x series. Interoperability with the AT Protocol and Tangled is a research topic, not a commitment.

Until then, Slath builds what federation depends on:

  • Stable change identity that doesn't break when a commit is rewritten, so a change can be referred to from elsewhere.
  • A complete REST API and webhooks, so other systems can follow what happens on an instance.
  • Full data export, so nothing you put into an instance is locked in.

If you work on ForgeFed, run a federated forge, or have opinions on how jj change identity should travel between instances, we'd like to hear from you early, while the data model is still open.

Roadmap

Releases have no dates. Each one ships when its acceptance tests pass, and those tests cover security, accessibility, and upgrades alongside features.

Planned releases up to 1.0
VersionThemeStatus
foundationWorkspace, hardened Git runner, job queue, Git over HTTPS and SSH, jj compatibility testsIn progress
0.1Self-hosted Git: accounts, tokens, SSH keys, organizations, repositories, code browser, API, backup and restorePlanned
0.2Team alpha: OIDC, TOTP, passkeys, teams, branch protection, issues, notifications, search, import, robust upgradesPlanned
0.3Merge requests and forks: revisions, interdiffs, batched reviews, suggestions, statuses, webhooks, bot accountsPlanned
0.4Stacks: per-change review, stack view, partial landing, landing by push, conflictsPlanned
0.5CI with GitHub Actions-style workflows on separate runners, with approval for external contributionsPlanned
0.9Release candidate: data export, performance, external security review, signed releasesPlanned
1.0Stable interfacesPlanned

Not in 1.0: federation, a package registry, Git LFS, wikis, code search, and Kubernetes-native high availability. Some of these are planned for later releases.
